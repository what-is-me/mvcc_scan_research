# 实验笔记 — 实证结论与分析记录

本文件是研究日志：记录定性结论、归因框架、方法论教训与未定案决策。
它**不是规范**——协议、不变式与契约的唯一权威是 AGENTS.md；两者冲突时
以 AGENTS.md 为准。本文里"待查 / 待验证"标注的条目是未闭合的问题，
不是结论。

**本文件有意不保存具体实测数字。**单一环境、单轮实验的绝对值与百分比
不可外推，留在文档里会锚定后续设计与实现的判断（快盘上的排序在慢盘上
会反转，见 §1.3 / §2 的"全驻留固定税"）。这里只沉淀方向性结论与因果
机制。原始数据随实验产生：本地在 `build/mingw/results_cmp/`（未提交），
CI 在 benchmark artifact；需要引用数字时按 §1 的命令重跑、从 JSON
现抽，不要从文档抄。

## 1. 本地对照实验：并发强度 × 扫描策略

环境：Windows/MinGW 本地机，NVMe 快盘。固定参数：基表池 32 MB
（≈ 表的 1/8）、LRU、表 200 万行 / 64 KB 页、扫描间隔 1000 ms。
四组：t8 / t16 / t32（线程数递增）与 z11（zipf1.1 + t8）。时长以
"扫描轮数足够"为准（§5）。

运行形式（`build/mingw/` 下）：

~~~
mvcc_exp scan_policy=<策略> tp_threads=<N> key_dist=<分布> \
         base_pool_mb=32 replacer=lru duration_s=<秒> --experiment-id=<组名_策略名>
~~~

注意：**defer_chain / defer_paged 未包含在本地组**（本地实验聚焦
bypass 问题），它们的本地行为只能从 CI 报告外推；引用"本地 baseline
最快"时别忘了这个缺口。

### 1.1 TP 吞吐是饱和吞吐

线程数成倍增加，吞吐同量级不动；换成 zipf1.1（热点集中、行冲突率
下降）吞吐显著上升。推论：吞吐瓶颈在行冲突与共享资源竞争，不在
线程供给；提高 TPS 的负载路径是键分布倾斜。已写入 AGENTS.md §11。

### 1.2 锁规避维度：只在最高并发档显现

t32（本组最高并发）下 combo 扫描延迟大幅领先 baseline，且 **TP 吞吐
反升**——扫描经池路径的 Fix 次数大幅减少后，池锁竞争下降，TP 的 Fix
不再与扫描排队。锁规避与 I/O 效率是 bypass 的两个正交收益来源，
已写入 AGENTS.md §10。

### 1.3 快盘低并发 = baseline 主场（I/O 维度收益趋零）

t8（TPS 无压力）下 baseline 最快，combo 落后。本地 NVMe 上一次直读
往返很便宜，而冷段直读按 miss 子段成批、散布热行把冷区切碎成大量
短 run，**读调用次数反而多于深度预取的 baseline**——调用粒度退化
是 bypass 在快盘上的真实成本，CI 慢盘上被物理页数的收益盖过。

### 1.4 hotfirst 无主场

四组全部垫底（延迟最差，多数组 TPS 也最差）。理论收益（先扫常驻页）
被两点抵消：kScan 访问模式下 baseline 顺序扫到热点页时它们同样在
池里（AGENTS.md §10 已记录）；热点段先扫意味着最先撞上 TP 正在
高频更新的页——锁位判定失败率最高的行集中在扫描最前面。

### 1.5 z11：combo 反而最慢（待验证假设）

zipf1.1 下 baseline 延迟反而下降（undo 全驻留时走链是纯内存操作，
链长不是问题），chain_avg_hops 显著上升（热行在窗口内积累的版本数
增多）。combo 明显落后。待验证假设：TP 写流量上升（undo 写回 +
淘汰）后，combo 的多次同步直读调用与写回竞争磁盘队列，单次调用
延迟放大——即 §1.3 的读调用成本被高写入负载放大。若成立，直读
调用粒度是 combo 在"快盘 + 高写入"区的系统性弱点，候选对策是
"整段连驻留页一起读、读后丢弃"（预取已接受同样的浪费，§7.5）——
属设计变更，须先改文档再动代码。

### 1.6 t16 combo 的 TPS 反常下降（未解释）

中档并发下 combo 扫描延迟领先但 TPS 反降，与最高并发档的方向相反。
锁规避收益与 I/O 开销的平衡点在哪、是否存在拐点，现有数据说不清。
这是 tp_threads 进矩阵（§6 决策 1）的直接动机：需要 CI 在多档并发
强度上复现。

## 2. CI 完整矩阵结论（shared runner，慢盘）

来源：benchmark workflow 多轮汇总报告（6 策略 × 4 替换器 × 池档位）。

- **组合可加性成立**：combo 与 hotfirst_bypass 的基表读几乎逐位
  相同，组合的增量收益全部来自 undo 侧——正是设计预期（基表页访问
  组织 × undo 解析时机正交，AGENTS.md §10）。
- **正反馈环反向兑现**：combo 的 undo 逻辑读比 defer_paged 还低——
  扫描快 → 快照窗口短 → 窗口内提交少 → 走链行少。defer 系解析的
  工作量与扫描时长正相关，这不是独立收益而是乘数。
- **全驻留固定税**：表全驻留（I/O ≈ 0）的池档位下 combo 慢于
  defer_paged——热段快照、哈希驻留判定、双 pass 在无 I/O 可省时
  全是纯开销。bypass 的收益有"必须存在可省的 I/O"这个前提。
- **替换器敏感性减半**：bypass 系策略跨替换器的延迟差异显著小于
  baseline 系——扫描绕开池路径后，替换器行为对扫描的影响被解耦。
- **runner 噪声识别**：个别池档位下出现过全部策略 TPS 同步大幅
  下挫，判定为 runner 干扰并剔除。识别规则已写入 AGENTS.md §12：
  跨策略一致的退化是环境信号，不是策略效应。

## 3. 热行分布核验（scattered 映射）

问题：热行会不会空间聚集，使实验测的是特例？核验方法：zipf0.8、
固定 seed 的全表随机置换，统计页级访问分布。结论：与"页内热点行
密度自然涌现"的散布水平一致，无超比例聚集的头部页，**无空间
聚集**——zipf 的倾斜在行级、通过置换表均匀摊到页级，符合
AGENTS.md §11 的设计意图。seed 固定，此核验可随时重放。

## 4. 代码与测试教训（实现 bypass / 组合策略过程中）

- **测试里 after 快照必须在提交之后取**：`HotFirstBypassSeesCommittedData
  AfterEviction` 首跑失败，原因不是实现而是测试自己在提交前取了
  read_ts——ts ≥ read_ts 按协议不可见（§9.2 判定即走链）。系统是对的，
  测试时序错了。
- **测试不能隐式假设池的驻留状态**：`BypassDeferMainKeepsUndoAndPool
  Untouched` 首跑失败，因为 UpdateRow 本身会把页 Fix 进池（小表 +
  小池恰好全装下），热段快照比测试预期的更大。写池相关断言前先算
  清楚测试自己触发了哪些装载。
- **扫描两种页内行处理共用一个 Impl**（OnRow 参数化）：池路径与
  bypass 路径的行逻辑只有"数据从哪来"不同，复制两份必然漂移。这是
  "优先复用而非重复实现"（§1）在扫描层的落点。
- **结构化编辑后必须读回现场**：一次 Edit 把相邻函数体误删，靠读回
  文件立即发现。批量改动后 grep 函数签名计数是最便宜的回归检查。

## 5. 方法论教训（实验与数据分析）

- **时长下限由扫描轮数决定**：短时试跑在最高并发组只跑得出 1 轮，
  p50 无意义。规则：信 p50 之前先看 `scan_count ≥ 3`。
- **先看 JSON 实际结构再写分析脚本**：字段名靠猜浪费了一轮。
- **凭记忆引用数字不可靠**：本文件初稿曾凭记忆写入数字，重抽全部
  JSON 核对后发现与口述数字有出入（幅度与所属组都有记错的地方）。
  结论必须重新来自数据——这也是本文件只存定性结论的直接原因：
  连刚测完的数字都记不准，隔了几个月更不可能凭文档数字做设计
  依据。

## 6. 未决决策（登记于 AGENTS.md §14，此处留定性证据）

1. **tp_threads 进 benchmark 矩阵**：区分度证据 = §1.2 / §1.6
   （锁规避收益随并发强度放大，且中档并发存在方向反转的未解释
   现象）。代价：6×4 矩阵 ×3 档 = 72 轮，CI 时长重估。
2. **undo 池档位维度砍除**：多轮 CI 均未改变策略间相对结论；undo
   侧差异在池全驻留时即已显现，档位只影响物理读绝对值。保留理由
   仅剩防 undo 池成为隐藏瓶颈（当前实验时长内 undo 文件远小于
   最小档位）。
